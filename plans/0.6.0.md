# 0.6.0: practical composite metrics

Status: release candidate prepared locally at version 0.6.0. No push, PR, tag,
or publication has occurred yet.

## Goal and target user

A product data scientist can take assigned-user and event tables, define a
scalar business metric, and obtain an explainable treatment-minus-control
interval without writing their own resampling or jackknife. Existing 1-D
comparisons must keep their API and seeded results.

## Scope and order

### 1. Joint multicolumn resampling — first implementation slice

- [x] Add explicit `allow_2d=True` to `bootstrap_two_sample`. Rows are units;
  columns are jointly observed features. The callable receives a numeric NumPy
  matrix and still returns one finite scalar, not one statistic per column.
- [x] Preserve column dependence for independent, paired, and clustered designs.
- [x] Generalize BCa leave-one-out buffers to delete whole rows/pairs; clustered
  jackknife continues to delete whole clusters.
- [x] Reject empty feature sets, incompatible shapes, and mismatched DataFrame
  column labels/order. Do not silently align paired data by pandas index.
- [x] Add `RatioOfSums(numerator=0, denominator=1)` as a scalar statistic;
  distinguish it from mean-of-ratios and the between-arm `effect='ratio'`.
- [x] Reject undefined/non-finite metrics, including invalid bootstrap or
  jackknife samples; do not omit, stabilize, or redraw those samples silently.
- [x] Test exact seeded distributions against independent reference loops,
  batch invariance, row/cluster deletion, and legacy 1-D behavior.

### 2. Explicit design validation — implemented

- [x] Add optional analysis-unit identifiers through a deliberately designed API.
  For independent user-level rows: uniqueness within arms and no cross-arm
  overlap. For paired rows: explicit correspondence checks.
- [x] Repeated-event cluster IDs are not necessarily globally namespaced. Never
  infer user overlap solely from equal arm-local numeric cluster labels.
- [x] Reject ambiguous/missing identifiers; do not reorder, aggregate, drop rows,
  or impute outcomes automatically.
- [x] Test DataFrame conversion and missing optional pandas independently.

### 3. Reporting and executable practitioner example — implemented

- [x] Add concise metric/design metadata to exports, without raw input data or
  serializing callables. Decide the field contract before implementing it.
- [x] Example: assigned users + order events -> user aggregates -> left join ->
  explicitly justified zero orders/revenue for non-buyers -> three distinct
  metrics (revenue/user, revenue/order, mean user ratio where defined).
- [x] State estimands, effect units, denominator changes, exclusions, and the
  distinction between uncertainty and a business shipping decision.
- [x] Preserve assigned users without observed events. Explain why conditioning
  on buyers is not an assigned-user analysis.
- [x] Execute the example offline in CI and verify reported values (pandas
  environments; dependency-minimum environments skip this optional integration).
- [x] Update README, experiment guide, limitations, API reference, and changelog.
  Do not claim the feature exists in the published 0.5.1 documentation.

### 4. Statistical and performance evidence — release gate

Runner implemented: `benchmarks/bench_composite_metrics.py` with quick,
validation, release, and statistical profiles, selected scenarios, per-cell
resume, source/commit/environment checks, explicit failure accounting, and
independent/cluster runtime measurements including bounded-vectorized IID SciPy.
Long evidence runs and the remote release CI gate are **not completed**.

- [x] Audit fixes: reject duplicate matrix-DataFrame column labels; preserve
  cluster-ID types/large-integer precision and reject incomparable labels.
- [x] Add known-truth dependent activity/price, covariance-change and clustered
  activity/price scenarios, with analytic-formula/large-population tests.

- Known-truth simulations with correlated numerator/denominator, zero-order
  users, unequal arm sizes, skew, unequal cluster sizes, and paired data.
- Include denominator changes and pathological low-information cases; report
  failures and invalid intervals instead of scoring only successful trials.
- Use independent deterministic data/resampling streams; report coverage,
  interval width, invalid counts, and Monte Carlo uncertainty per cell.
- Use exact reference distributions/jackknife for implementation checks;
  compare compatible scenarios with SciPy and delta-method approximations.
  Agreement with SciPy alone is not proof of nominal coverage.
- Targeted runtime/memory measurements for the new path: user-level ratio,
  clustered ratio, and BCa at growing unit counts. Include bounded vectorized
  references where possible. Distinguish allocations from process RSS.
- Keep fast pipeline smoke tests in CI. Long runs must checkpoint/resume and
  pin the candidate commit and environment. Do not rerun all historical
  benchmarks or relabel their results as 0.6.0 evidence.
- Final gate: lint, strict typing with/without Numba, full regression tests,
  minimum dependencies, all supported Python/OS CI checks, notebook execution,
  strict docs, archive metadata/contents, and installed-wheel smoke checks.

## User validation alongside implementation

Invite 3–5 practitioners to run an actual workflow, not just review a demo.
Record data-preparation friction, misunderstandings of estimands, workaround
code, runtime constraints, and whether they use the library for a second
analysis. This is a validation target, not evidence of existing adoption.

## Explicitly outside this release

- Multi-metric joint results and simultaneous intervals/multiplicity control.
- Two-sample stratification and weighting: separate methodological design.
- Automatic shipping recommendations, p-values, or sequential guarantees.
- Approximate bucketing before demonstrating a need and quantifying its error.
- New survey, multiway clustering, or group-aware ML-validation methods.
